## 3. 接缝策略：一条长卷切三段

### 3.1 做法

不做镜像、不重复、不逐段独立出图。每区域先出 **一张连续超宽长卷**，再按像素列切成 3 段：

| 步骤 | 操作 | 参数 |
| --- | --- | --- |
| 1 | 生成连续长卷（一次出图，构图横跨 3 个景别） | `5760×1200`（或 `4800×1000`），比例 4.8:1 |
| 2 | 裁掉出图工具右下角水印 | 右裁 260 px、下裁 130 px |
| 3 | 居中裁到 4.8:1，再 LANCZOS 降到 4320×900 | 只做一次重采样 |
| 4 | 按 `x=0/1440/2880` 直切 | 输出 `maps/<region>_1|2|3.png` |
| 5 | 拼回 4320×900 与第 3 步结果逐像素比对 | 差值应 ≈ 0 |

因为第 2 段左缘的列就是第 1 段右缘的**下一列**，相邻段拼起来是同一幅画的原像素，**结构上不存在接缝**，也不需要羽化、重叠或镜像。

### 3.2 可验证判据

| 判据 | 阈值 | 说明 |
| --- | --- | --- |
| 相邻段边缘列平均绝对差 `mean_abs` | ≤ 同图自然相邻列基线的 1.2 倍 | 不是缝，只是正常渐变 |
| 单列最大绝对差 `max_abs` | ≤ 30（8bit） | 超过说明该处有硬边（如建筑轮廓正好压线） |
| 拼回长卷 diff | ≈ 0 | 3 段首尾相接必须还原第 3 步图像 |
| 重复构件检测 | 无 | 同一房檐/灯笼串不得在两段重复出现 |
| 方向检测 | 无翻转 | 招牌、屋脊、水流方向连续 |

云京实测（长卷 `pano_taoyuan_a`，5760×1200）：

| 接缝 | mean_abs | 同图基线 mean | 结论 |
| --- | --- | --- | --- |
| `taoyuan_1 → taoyuan_2` | 4.38 | 6.54 | 低于基线，无硬缝 |
| `taoyuan_2 → taoyuan_3` | 4.64 | 6.54 | 低于基线，无硬缝 |

（`max_abs` 本次未落盘记录，正式验收由脚本一并输出。）

### 3.3 失败退路

若某区域长卷出图出现「3 段明显是 3 张画拼的」（透视断裂 / 建筑突变 / 天色跳变），处理顺序：
1. 换后缀重生成同区域长卷（提示词强化「one continuous scene / unbroken street」）；
2. 仍失败则把该区域拆成「1 张长卷 + 1 张只补中段的长卷」并让中段两侧各带 ≥120px 重叠区，用重叠带做平滑过渡；
3. 仍失败才上报，不允许退回镜像或重复铺段。

## 7. 战斗背景（4 张 1440×900）

### 7.1 构图硬约束

| 项 | 要求 |
| --- | --- |
| 地平线 | `y=240~300`（远山/城墙压在此线上方） |
| 敌方站立带 | `x=120~380`，地面必须连续覆盖 `y=280~860` |
| 宠物站立带 | `x=880~1070`，地面连续覆盖 `y=270~845` |
| 我方站立带 | `x=1100~1300`，地面连续覆盖 `y=320~840` |
| 中央过渡区 | `x=420~860` 只作纵深过渡，可放木桥、水面、碎石，**不放高过 y=700 的实体**（避免挡飘字） |
| 地面材质 | 石板/泥地/木桥面，纹理朝镜头方向（纵向）延伸，表现透视 |
| 不可站 | 水面、悬崖外、屋顶、山体：其顶边不得高于对应槽位脚底 `y` |
| 光影 | 主光左上，角色脚下有柔和接触阴影（背景自带，不额外画） |
| 远期元素 | 顶部 1/3 留雾与空天，便于 UI 压条与飘字 |

## 9. 命中帧与结算对齐

### 9.1 结论（先看这里）

| 项 | 值 |
| --- | --- |
| attack 命中帧 | **`attack_3`（第 4 帧，索引 3）** |
| attack 命中帧时间窗 | 索引 3 覆盖 **250~333 ms**，取结算点 **300 ms** |
| cast 释放帧 | **`cast_2`（第 3 帧，索引 2）** |
| cast 释放时间窗 | **250~375 ms**，取结算点 **300 ms** |

### 9.2 与代码现有延时的实测差

代码侧事件链（`battle-screen.ts`）：`attack` 事件 → 等 `DELAYS.attack=520ms` → `damage` 事件（飘伤害字）→ 等 `DELAYS.damage=500ms`。

| 方案 | 做法 | 飘字时刻 | 视觉结果 | 评价 |
| --- | --- | --- | --- | --- |
| A（推荐） | `DELAYS.attack` 520 → **300**，`damage` 保持 500 | 300 ms | 飘字正好压在 `attack_3` 全展帧上 | 打击感对齐，改动一行 |
| B | 代码不动，仍 520 ms | 520 ms | 落在 `attack_5` 播完后的空档（500~520 ms），命中感偏晚 | 不改代码但手感钝 |
| C | 美术把全展帧挪到 `attack_5`，命中在 416~500 ms | 520 ms | 全展与飘字差 20~100 ms | 需要重画全部 15 套 attack，不划算 |

> 建议走 A：美术统一按 `attack_3` 命中、`cast_2` 释放出图；代码把 `DELAYS.attack` 调成 300、`DELAYS.cast` 调成 300，`DELAYS.damage` 与 `DELAYS.death` 不动。
> 若坚持「与 500 ms 延时严格对齐」，则命中帧应设计在 `attack_5` 末（t=500 ms），但需接受「挥完才掉血」。本条请评审二选一。

## 10. 状态机

| 当前态 | 触发 | 目标态 | 规则 |
| --- | --- | --- | --- |
| idle | 水平速度大于 0.1 | walk | 立即切，从 `walk_0` 起播 |
| walk | 水平速度不大于 0.1 | idle | 立即切，从 `idle_0` 起播 |
| idle / walk | 攻击指令 | attack | 播一次（不循环），播完回 idle；期间锁移动输入 |
| idle / walk | 施法指令 | cast | 播一次，播完回 idle；期间锁移动输入 |
| attack / cast | 收到 `dead` | dead | 可被死亡打断，立刻切 dead |
| 任意 | hp ≤ 0 | dead | 播一次，**停在 `dead_2` 末帧**，保持 `DELAYS.death=900ms` |
| dead（保持结束） | 计时到 | fade → difu | 400 ms 淡出 → 传送到 `difu_1 (720,700)` → 200 ms 淡入 → idle |
| dead（difu 内再次阵亡） | 计时到 | difu 复活点 | 原地复活（不重复传送） |

补充规则：

1. `hurt` 不出动画，只做 120 ms 红色 flash + 轻微位移抖动，**不要**新建 `hit` 序列。
2. attack / cast 期间不可被攻击打断（除死亡），避免动作卡在半途。
3. walk 循环时长 444 ms，与移动速度解耦：脚底滑步按 `速度 × 0.444 / 步幅` 校准，步幅按 128px 帧约 46px 计。
4. 死亡后角色仍占槽位 400 ms（淡出期间），避免瞬间空槽。
