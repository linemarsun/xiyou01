# 山海奇谭 · 功能说明

> 本文描述**当前代码实际具备的功能**（对应 `dev-continue` 分支 / `origin/dev` 基线）。
> 接口签名见 [接口说明.md](./接口说明.md)，运行与操作见 [使用方式.md](./使用方式.md)。
> 进度与待办以 [../PROGRESS.md](../PROGRESS.md) 为准，本文只讲功能本身。

## 1. 项目定位

一款大话西游式 **2D 回合制 RPG** 的原创实现。只借鉴回合制玩法机制，**美术、名称、文案、素材全部原创**，不使用任何网易素材，也不复用其角色/门派名称。

| 项 | 内容 |
| --- | --- |
| 技术栈 | TypeScript 5.9（strict）、Vite 7、PixiJS 8 |
| 运行形态 | 纯前端单页应用，存档在浏览器 localStorage |
| 分层 | `src/core/` 纯逻辑（禁止 import DOM）→ `src/render/` PixiJS 渲染 → `src/ui/` DOM 界面 |
| 素材 | `tools/gen-assets.mjs` 程序化生成像素画与场景图，输出 `public/assets/` |
| 联机预留 | 指令与事件均为可序列化纯对象；客户端上行 `Command[]`，服务器跑同一份 `resolveRound` 下发 `BattleEvent[]` |

## 2. 架构与数据流

```
选人 setup-screen ── newGame() ──> GameState
                                     │
世界 world-screen ── WorldRenderer ──┤ 点击地面/NPC/路牌/怪物
                                     ├─> onNpc / onExit / onEncounter
                                     │
                          BattleOptions（等级/装备/加点/师门/宠物/背包）
                                     │
战斗 battle-screen ── Battle ────────┤ 每回合 playerCommands → resolveRound()
                     BattleRenderer  │        ↓
                                     └── BattleEvent[] → DOM 日志 + PixiJS 动画
                                                  ↓
                               BattleHooks.finish() → settleBattle() → 存档
```

约定：**渲染层与 DOM UI 都只消费事件流**，不直接读引擎内部状态（播放期间 `battle-screen` 自己按事件维护 `uiUnits` 快照）。这是联机时"服务器授权"的基础。音频层同样只消费事件流（`core/audio-map.ts`）。

目录补充：`src/core/audio-map.ts`（事件→音效名纯映射）、`src/audio/audio.ts`（Web Audio 发声与 BGM）。

随机数分工：战斗内一切随机走 `core/rng.ts`（mulberry32，种子化，同种子 + 同指令 ⇒ 同结果）；世界侧掉落/怪物游荡用 `Math.random()`，无需回放。

## 4. 战斗系统

### 4.1 回合流程
1. 回合开始，为己方**每个存活单位**（主角 + 出战宠物）依次下指令：攻击 / 法术 / 道具 / 防御 / 捕捉（仅主角）。
2. 点「出手」→ `Battle.resolveRound(playerCommands)` 生成敌方 AI 指令，与己方指令合并。
3. 全体按 `spd` 降序执行（同速按开局随机 `tiebreak`），逐个产生事件。
4. 回合末：蚀毒结算 → 法力回复 → 状态递减（防御姿态当回合末消失）。
5. 任一方全灭即 `battleEnd`，UI 顺序播放事件流并展示结算浮层。

### 4.2 职业与法术
四门派（原创命名）：云岚·司礼府（人，武技 + 混乱/封印/昏睡三控）、霜华·琼霄仙府（仙，风/火/雷/水四系，含群体风法）、玄烬·玄炎魔窟（魔，加攻/重击/摄血吸血）、冥汐·忘川幽祠（鬼，遗忘/三尸蛊毒/鬼火）。

师门法术等级（`core/skill.ts`）：`L = level - 1`
- 物理技能威力 ×(1 + 0.06L)，法术威力 ×(1 + 0.07L)；
- 控制基础命中 +1.5L（封顶 95），毒伤 +8L，增益幅度 +2L；
- Lv≥6 时状态/增益持续回合 +1；MP 消耗 `基础 + 2L`；
- 修炼到下一级消耗 `40×(level+1)` 银两 + `(level+1)` 潜能点。

### 4.3 状态与抗性
混乱（敌我不分）、昏睡（受击即醒）、封印（跳过行动）、遗忘（非物理技能失效）、蚀毒（回合末固定掉血）、攻升、防升、防御（受伤减半，仅本回合）。
控制命中 = `clamp(基础命中 − 目标对应抗性, 5, 95)`；元素抗性影响法术伤害系数：`(100 − min(抗性,75)×0.6)/100`。

### 4.4 伤害公式（`core/battle.ts`）
- 物理：`攻击力 × 攻升倍率 × 技能倍率 × 100 / (100 + 目标防御)`；普攻与物理技能可会心（8% 概率 ×1.6）。
- 法术：`法强 × (威力/100) × 元素系数`；不判定会心。
- 减伤：防御姿态 ×0.5；防升 ×(1 − 百分比/100)；最终伤害至少 1。
- 吸血技能按实际造成伤害的比例回血；每回合末法力回复 `max(3, round(maxMp×0.08))`。

### 4.5 捕捉
成功率 `0.2 + (1 − 目标当前气血/最大气血) × 0.55`；仅人物可下达，仅野怪可收服，`shanxiaowang`（洞天山魈王）不可收服。成功后该单位退场并记入 `Battle.caught`，结算时加入宠物栏。

### 4.6 AI 与自动战斗
敌方 AI（`core/ai.ts`）优先级：自身增益 → 控制（挑对应抗性最低的目标，对面全是物理怪时不浪费「遗忘」）→ 输出技能 → 普攻；一半概率补刀残血。自动战斗复用同一套规划，额外增加"气血 < 40% 且有金疮药时优先嗑药"。

## 5. 世界系统

### 5.1 地图
云京（安全区，玄鹤长老 / 酒肆）→ 青崖山道 → 渡忘川 / 玲珑洞天 → 忘川南渡口 → 地府（战败重生）→ 还阳回云京。五张**各自独立的等距格网**（菱形 64×32，`ISO_GRIDS` 逐图定义，`ox = rows×32 / oy = 16`）：云京 128×128 → `8192×4096`、山道 128×96 与忘川 96×128 → `7168×3584`（歪斜方向相反）、洞天 104×104 → `6656×3328`、地府 80×112 → `6144×3072`。`bounds = {0,0,w,h}` 覆盖整个菱形（边界格 y 最低 16px，不能用旧卷轴的内缩裁掉），具体可走性由 `iso.buildCollision()` 与布局 JSON 取交。地面 / 构件由 `public/assets/art/iso/<region>.json` 描述，渲染层按视口裁剪合成。怪物在出生点附近游荡，靠近触发遭遇战；点路牌 / NPC / 怪物会经格级 BFS 自动吸附到最近可走格。切图会重置该图的 `killedGroups`（重新刷怪）。长老与酒肆在云京市集广场；**所有出入口位于格网边界带**，成对路牌互为对方落点，源格按本图格网、落点按目标图格网换算。水面不可走、石桥桥面可走、牌坊券洞可穿行。

### 5.2 任务链
`QUESTS` 顺序解锁，回云京向长老交付：

| 任务 | 目标 | 奖励 |
| --- | --- | --- |
| 青崖清狼 | 击杀青崖苍狼 ×3 | 100 银 + 金疮药 ×2 |
| 忘川镇骨 | 击杀忘川骨卒或幽丝蛛妖 ×4 | 160 银 + 凝气丹 ×2 |
| 洞天讨魈 | 讨伐洞天山魈王 ×1 | 300 银 + 金疮药 ×2、凝气丹 ×1 |

### 5.3 经济与成长
- 银两、经验按怪物种类结算（表 `SILVER_PER_KILL` / `EXP_PER_KILL` 在 `core/world.ts`）；战斗掉落丹药（35% / 25%），头目必掉极品装备，普通怪 18% 掉装备。
- 人物升级需求 `40 + 35×当前等级`，每级 +5 潜能；四维加点：力量（攻+2）、根骨（气血+12 防+1）、灵性（法+2 法力+8）、敏捷（速+2）。
- 出战召唤兽分得一半经验，升级需求 `30 + 25×等级`，每级全属性 +8%。
- 装备三部位（武器/护甲/饰品）× 三品阶（凡品/良品/极品），基础属性固定、词条可花 30 银炼化重掷；背包上限 12、宠物栏上限 6。
- 加点和装备的合计加成经 `totalBonus(gs)` → `BattleOptions.playerBonus`，**只作用于主角**，下一场战斗生效。

### 5.4 存档
localStorage 键 `shanhai-save-1`。`saveGame` / `loadGame` / `clearSave`；`loadGame` 对旧存档逐字段兜底迁移（宠物个体化、等级、装备、加点、潜能按等级补发）。任务进度、战斗结算、切图、面板操作均自动落盘。

### 5.5 装备系统补全（模块 2 采用的设计约定）

- **宠物装备位**：出战召唤兽可穿戴**护甲 / 饰品**两个部位（设定上不持械）；与人物共用背包，`isEquippedAnywhere` 保证同一件装备不会被人物或任一召唤兽重复穿戴。宠物加成经 `BattleOptions.petBonus` 只作用于宠物，人物加成经 `playerBonus` 只作用于主角。
- **掉落池品阶**：`DROP_TIER_WEIGHTS` 定义每种怪物的 `[凡品, 良品, 极品]` 权重（青崖苍狼 `80/20/0`、玄石熊罴 `40/50/10`、山魈王 `0/20/80` 等）；一组怪取组内品质期望最高者作为该组掉落池。装备总掉率不变（普通 18%、头目必掉）。
- **极品稀有词条**：极品装备每条词条有 25% 概率成为 ★稀有词条，数值 ×2；描述前加 ★、背包列表金色显示。**炼化会重掷，稀有词条不永久保留**。
- **洗点丹**：世界侧消耗品 `inv.respec`，不进入战斗道具系统（战斗引擎零改动）；使用后清空四维加点并全额退还潜能点。获取途径：青崖清狼奖励 ×1、头目战必掉 ×1、普通战斗 8% 掉落。

### 5.6 宠物炼妖（模块 3 / M3d 采用的设计约定）

- **入口与限制**：「🐾 宠物」面板底部「⚗ 炼妖」，用两个下拉选两只**非出战**召唤兽；出战宠物不允许参与，避免合成后 `activePetUid` 失效。消耗 `FUSE_COST = 100` 银两。
- **结果规则**：物种在两只中二选一（各 50%），等级取两者较高、经验清零；技能取双方并集去重后最多保留 3 个；另有 20% 概率从通用技能池领悟 1 个新技能（总上限 4）。
- **成长系数**：`growth` 随机 `1.00~1.20`，叠乘在 `petGrowth(level)` 之上（`petUnitStats` 使用两者乘积）；宠物面板显示 `×1.10` 之类的系数。装备不继承、出战宠物不变。
- **通用技能池**：新增 `pt_xue` 噬血爪（物理 + 吸血）、`pt_dun` 玄岩甲（防升增益）、`pt_lei` 引雷诀（雷系法术）三个原创技能，注册在 `SKILLS` 表，仅通过炼妖领悟。
- 战斗侧通过 `petUnitSpec(inst)` 取「成长后属性 + 炼妖后的技能表」，非炼妖宠物自动回退到物种原始技能。

### 5.7 组队同伴（模块 4 采用的设计约定）

- **入口**：云京新增「云京酒肆掌柜」（复用 `elder` 精灵，仅位置/名牌区分），走近自动弹出酒馆面板；HUD 显示 `👥 同伴 N/2`。
- **模板与费用**：三种固定同伴——忘川引灯人（遗忘/毒/鬼火）、琼霄云游使（四系仙法）、玄炎墨刀客（加攻/重击/摄血），各 `HIRE_COST = 150` 银；**复用现有职业数值、技能与精灵素材，不新增美术**。上限 `COMPANION_CAP = 2`，解雇不退款。
- **战斗**：同伴经 `BattleOptions.companions` 以 `tag: 'companion'` 加入己方，与主角共用人物排站位（宠物排独立）；指挥阶段与自动战斗都会为同伴下指令；**同伴不可使用捕捉**（引擎侧限制 `actor.tag === 'player'`）。
- **成长**：同伴不吃经验，胜利结算时等级统一同步到人物等级；属性按 `companionGrowth(level) = 1 + 0.06×(等级−1)` 缩放，技能按 1 级生效（不消耗玩家潜能/银两修炼）。
- 存档新增 `companions` 字段，旧存档读档时补空数组。

### 5.8 音乐音效（模块 5 采用的设计约定）

- **零素材**：全部用 Web Audio 振荡器/白噪声实时合成，不引入任何音频文件，也不新增第三方依赖。
- **分层**：`core/audio-map.ts` 是纯函数 `sfxForEvent(BattleEvent) => SfxName | null`（可被回归断言、联机语义一致）；`src/audio/audio.ts` 是浏览器层单例，只负责发声与 BGM。core 仍不碰 DOM/Web Audio。
- **BGM**：三档场景 `setup / world / battle`，间隔 620 / 460 / 260 ms，战斗档更快并叠低音；进入界面时 `audio.setScene()` 切换。
- **音效**：攻击、施法、受伤、治疗、状态、倒下、收服、道具、胜/负共 11 类；由 `commitRound` 的事件循环按映射触发，`roundStart` / `actionStart` / `mpChange` 等静默。
- **自动播放策略**：首次 `pointerdown` / `keydown` 才创建或恢复 AudioContext；静音开关出现在选人、世界 HUD、战斗页三处，偏好存 `localStorage['shanhai-audio-muted']`，主音量 0.18。

### 5.9 自动战斗 + 自动寻路（模块 6 采用的设计约定）

- **形态**：HUD 新增「🤖 挂机」总开关（模块级状态，切图/战斗返回重建界面时保持，**刷新页面后自动关闭**）。开启后自动完成「找怪 → 走过去 → 触发战斗 → 战斗内自动战斗 → 结算 → 继续」，并支持**跨图巡游**与**自动回云京接/交任务**。
- **寻路**：新增 `core/path.ts`，输出 `waypoint` 队列；渲染器逐段行走。当前策略按你的选择为**单段直线 + 可行走区钳制 + 目标吸附**（地图无障碍物数据，不做 A*/绕障）；调用方只消费 `waypoints`，未来换 A* 网格只需替换 `planPath`。点击地面/路牌/NPC/怪物与挂机移动**共用同一条路径管线**。
- **挂机决策**：`core/autoplay.ts` 的 `nextAutoAction(gs, playerPos)` 为纯函数，优先级：丹药耗尽 → 任务接取/交付 → 当前图最近的未清怪组 → 按 `AUTO_ROUTE` 跨图巡游（出口用 BFS 求第一跳）→ 停止。怪物会游荡，因此追它们的**当前坐标**而非出生点，并每 1.6s 重新决策。
- **战斗接管**：`BattleHooks.autoBattle` 让每场战斗自动开启自动战斗，无需每场手点；玩家在战斗内关掉自动 → 通过 `onAutoOff` **终止整轮挂机**（手动优先）。
- **停止条件**：败北、丹药耗尽、任务链全部完成、无怪可打、手动关闭总开关、或战斗内切回手动指挥，都会自动停机并提示原因。
- **补给边界（重要）**：当前**没有商店系统**，因此「补给」只实现为"任务交付时自动领取含丹药的奖励"；金疮药与凝气丹都归零时挂机自动停止并提示手动补给，**未自行新增商店/购买逻辑**。
- 切图会重置 `killedGroups` 重新刷怪，因此跨图巡游可持续；该状态不写入存档。

### 5.10 分块大地图（模块 7 采用的设计约定）

> 历史约定：以下为当时分块卷轴的设计记录。现行五图已改为等距构件体系（见 5.13），`WORLD_SCALE` / `syncTiles()` 仅作回退保留。

- **为什么不是单张 50 倍 PNG**：线性 50 倍 = `72000×45000`（32.4 亿像素/张、约 13 GB 内存），远超 WebGL 纹理上限（8192~16384），且视口 960×520 只占地图约 1.3%，横穿一次要 6 分钟，可玩性差。用户确认改走**分块地图**，倍数由我按可玩性决定。
- **默认倍率**：`WORLD_SCALE = 8` → 单张 `11520×900`（面积 8 倍）。**架构支持任意倍率**：只改这一个常量即可到 50 倍（72000 宽），内存不变，只是跑图时间变长；`WORLD_MAPS` 由 `expandMap()` 按区段程序化生成，无需手改坐标。
- **为什么只扩横向**：保持纵向 900，天空/地平线始终在顶部，tile 整图横向平铺不会出现"第二个天空"；镜头视口 `960×520`、精灵缩放、触发距离、怪物游荡范围**全部不用改**，局部手感与原来一致。
- **分块渲染**：`render/world-renderer.ts` 只保留覆盖镜头的 1~2 个 tile Sprite，随摄像机移动创建/回收（`syncTiles()`），内存与地图总宽度无关；`manifest.json` 的 `$worldTiles` 为每张地图提供 **4 个视觉变体**（`world_<id>_0..3.png`），按列号轮换缓解重复；生成器去掉了左右暗角，避免拼接处出现周期性暗边。`$scenes` 的世界键保留并指向 `_0` 变体，兼容旧读取路径。
- **补内容**：怪组按 8 个区段等比例复制（青崖山道 4→32 组），每 2 个区段复制一组完整出口；NPC/酒馆留在起点区段。走路速度 `135 → 200 px/s`（用户选择），减少跨区段跑动时间。
- **素材生成安全性**：`npm run assets` 不再递归删除 `public/assets/`，改为原地覆盖（保留手工替换的素材，也避开受限环境的删除保护）；旧版单张 `world_*.png` 若残留不再被清单引用，可手动清理。
- **存档兼容**：地图 id 与起点坐标不变，旧存档可直接读；`killedGroups` 旧键仍对应前几组怪，新增区段怪组默认为未清除。

### 5.14 一景一制（模块 12 现行设计约定）

- **用户反馈与取舍**：① 每场景要有自己的特色，不要千篇一律；② 规模参考云京但不要求完全一致，形状也可以不同；③ 地图切换的出口和入口要在边界上。模块 11 的四图虽换了配色，仍是同一套 128×128 十字主街 + 中心广场 + 中心券门，本轮把「骨架」也拆开重做。
- **独立格网**：`core/world.ts` 导出 `ISO_GRIDS: Record<string, IsoGrid>`（旧 `ISO_GRID` 保留为云京别名）、`isoGridOf(id)`、`isoWorldSize(g)`。菱形的胖瘦与歪斜方向由 `cols/rows` 比例决定：`ox = rows×32 / oy = 16` 使 cell(0,0) 上顶点贴 (0,0)，世界 `w=(cols+rows)×32 / h=(cols+rows)×16`。`expandMap()` 的等距分支自动推导 `w/h/bounds`，不再手写像素尺寸。
- **四套专属路网**（`tools/gen-iso-maps.mjs` 每图一个 `build(ctx)`，生成器末尾自带四邻接 BFS 自检）：
  - 青崖山道 `switchback-ridge`：128×96 横向偏斜；「之」字盘山栈道 + 环山回路 + 山腰歇脚坪，三条蜿蜒溪涧 + 四座石桥，三个山口各一牌坊，圆冠林海。
  - 渡忘川 `diagonal-river`：96×128 反向偏斜；宽 9 格斜河贯穿全图 + 两岸平行石堤 + 六座跨河石桥 + 南北渡口广场，枯木、芦苇、望乡台。
  - 玲珑洞天 `ring-cavern`：104×104 规整但更小；青苔环廊 + 青石圆厅 + 四条青石放射阶道 + 四段城墙洞壁 + 晶柱阵 + 洞顶暗河，只有西口可出入，另三口是观景死路。
  - 地府 `straight-road`：80×112 最窄长；一条笔直黄泉道 + 忘川横河 + 唯一奈何桥 + 两侧碑阵与引魂灯，孟婆在桥南。
  - 云京 `walled-city` 保持既有城制样板（128×128、闭合城墙四门、中心鼓楼、四坊）。
- **边界出入口契约**：所有路牌与跨图落点满足 `gx ∈ {1, cols−2}` 或 `gy ∈ {1, rows−2}`；成对路牌互为对方落点，玩家一进图就站在回程牌上。拓扑：云京(16,1) ⇄ 山道(32,1)、山道(1,62) ⇄ 忘川(11,1)、山道(126,62) ⇄ 洞天(1,52)、忘川(73,126) ⇄ 地府(40,1)，地府(40,110) 单向还阳回云京。`isoExit()` 的 `toX/toY` 必须用**目标图**的 `ISO_GRIDS[to]` 换算，两张图尺寸不同时不能共用一套。
- **锚点与回归**：布局 JSON 写 `grid / signature / tagline / size / anchors`，`BASE_MAPS` 逐条对应；`npm test` 61 项校验独立格网与形状互异、尺寸由格网推导、边界出入口与落点、落点即对方边界路牌、全锚点两两 BFS 连通、四种路网签名与地表组合互异、水面 / 桥面 / 牌坊券洞规则。生成器幂等，改布局后跑 `npm run maps && npm test`。
- **已知边界（模块 11 时期，已被模块 14 取代）**：当时野外构件以程序化占位为主、未新增美术 PNG；`v0.15.0` 起已用 12 张真实 PNG 补齐全部缺图构件，程序化占位退化为缺图回退。`art/maps/<region>_0.png` 旧满幅背景仅作布局加载失败时的回退。

## 6. 数值仿真

地址栏加 `#sim`：用 AI 执挥双方，每个职业跑 36 场（三种遭遇轮换），输出胜率、平均回合数、胜场平均回合数。用于调整 `core/content.ts` 数值后快速验证平衡。
