# 山海奇谭 · 接口说明

> 面向开发者：记录各层**对外暴露的类型、函数、类、钩子与数据契约**。
> 功能背景见 [功能说明.md](./功能说明.md)，运行与操作见 [使用方式.md](./使用方式.md)。
> 签名以当前 `dev-continue` 分支代码为准；加 `*` 的为模块内私有、不供外部调用。

## 1. 分层约束

| 层 | 目录 | 允许依赖 | 禁止 |
| --- | --- | --- | --- |
| 逻辑层 | `src/core/` | 仅 core 内部、标准库 | 禁止 `import` DOM；指令与事件必须是可序列化纯对象 |
| 渲染层 | `src/render/` | core 类型 + PixiJS | 不直接改游戏状态，只消费事件流 |
| 界面层 | `src/ui/` | core + render + DOM | 业务逻辑下沉到 core |

联机约定：客户端上传 `Command[]`，服务器运行同一份 `Battle.resolveRound()`，下发 `BattleEvent[]`；渲染与 DOM 只消费事件流。

## 2. `core/types.ts` — 类型与常量

### 基础枚举与映射

| 名称 | 类型/值 | 说明 |
| --- | --- | --- |
| `Side` | `'ally' \| 'enemy'` | 阵营 |
| `Element` | `'physical' \| 'fire' \| 'water' \| 'wind' \| 'thunder'` | 伤害元素 |
| `ELEMENT_NAMES` | `Record<Element, string>` | 日志用中文名 |
| `StatusKind` | `chaos \| sleep \| seal \| forget \| poison \| atkUp \| defUp \| defend` | 状态种类 |
| `STATUS_META` | `Record<StatusKind, {name, chip, bad}>` | 状态中文名/单字章/是否负面 |
| `ResistKey` | 五控制 + 四元素抗性键 | 抗性维度 |
| `Resists` | `Record<ResistKey, number>` | 抗性数值（0~100，越高越抗） |
| `resistKeyOf(kind)` | `(StatusKind) => ResistKey \| null` | 控制状态 → 抗性键；增益/防御返回 `null` |

### 核心数据结构

```ts
interface StatusInstance { kind: StatusKind; rounds: number; power?: number; appliedRound: number }

  drain?: number;      // 物理技能吸血比例
```

### `Command`（上行指令，可序列化）

| 变体 | 字段 | 说明 |
| --- | --- | --- |
| `attack` | `actorId, targetId` | 普通攻击 |
| `skill` | `actorId, skillId, targetId` | 施法；群体/自身技能 `targetId` 可为空串/自身 id |
| `defend` | `actorId` | 防御姿态 |
| `item` | `actorId, itemId: 'heal' \| 'mana', targetId` | 使用道具 |
| `catch` | `actorId, targetId` | 捕捉野怪 |

### `BattleEvent`（下行事件流，可序列化）

| `t` | 附加字段 | 时机 |
| --- | --- | --- |
| `roundStart` | `round` | 回合开始 |
| `actionStart` | `actorId` | 某单位开始行动 |
| `actSkip` | `actorId, reason: 'sleep' \| 'seal'` | 昏睡/封印跳过 |
| `actOverride` | `actorId, reason: 'chaos' \| 'forget' \| 'exhausted'` | 混乱/遗忘/法力不足改普攻 |
| `cast` / `attack` / `defend` | `actorId`（`cast` 另有 `skillId`） | 动作播报 |
| `damage` | `sourceId, targetId, amount, element, crit, hpAfter` | 伤害结算 |
| `heal` | `sourceId, targetId, amount, hpAfter` | 回血/吸血 |
| `mpChange` | `targetId, delta, mpAfter` | 法力变化（含回合末回复） |
| `statusHit` / `statusResist` | `targetId, kind, rounds?` | 状态命中/被抵抗 |
| `statusEnd` | `targetId, kind, reason: 'expire' \| 'woken'` | 状态结束 |
| `poisonTick` | `targetId, amount, hpAfter` | 蚀毒回合末结算 |
| `death` | `targetId` | 倒下 |
| `catchSuccess` / `catchFail` | `targetId, defId? / chance` | 捕捉结果 |
| `itemUsed` | `actorId, itemId, remain` | 道具消耗 |
| `battleEnd` | `winner: Side, rounds` | 战斗结束 |

## 3. `core/battle.ts` — 战斗引擎

```ts
interface AllySpec {
  defId: string; name: string; emoji: string;
  stats: UnitStats; resists: Resists; skillIds: string[];
}

interface BattleOptions {
  encounterId: string;        // ENCOUNTERS 的 id、'random'，世界模式传 'custom'
  classId: string;
  petId?: string;             // 无 petUnit 时的初始宠物物种
  playerName: string;
  seed: number;
  enemyIds?: string[];        // 世界模式直接指定怪物组，绕过 ENCOUNTERS
  encounterName?: string;
  sceneId?: string;           // 渲染场景键（地图 scene）
  startItems?: { heal: number; mana: number };
  playerBonus?: Partial<StatBonus>;   // 只作用于主角
  petBonus?: Partial<StatBonus>;      // 只作用于出战召唤兽
  companions?: AllySpec[];            // 酒馆雇佣的同伴，进入人物排
  skillLevels?: Record<string, number>;
  petUnit?: AllySpec;         // 召唤兽实例规格
}

class Battle {
  readonly seed, encounterId, encounterName, sceneKey: string/number;
  readonly units: Unit[];
  round: number; over: boolean; winner: 'ally' | 'enemy' | null;
  readonly items: { heal: number; mana: number };
  readonly usedItems: { heal: number; mana: number };  // 结算时回扣背包
  readonly caught: string[];                            // 本场收服的 defId
  unitById(id): Unit | undefined;
  aliveOf(side: Side): Unit[];
  snapshot(): Unit[];                 // structuredClone 只读快照
  planAllyAutoCommands(): Command[]; // 使用战斗内 RNG，可回放
  resolveRound(playerCommands: Command[]): BattleEvent[];
}
function elementName(e: Element): string;
```

`resolveRound` 行为：递增回合 → 生成敌方 AI 指令 → 合并指令 → 按 `spd`/`tiebreak` 排序执行 → 回合末毒/回蓝/状态递减 → 判定胜负。返回按时间排序的事件数组，UI 顺序播放即可。

## 4. `core/ai.ts` — AI 规划

```ts
function planCommands(selfSide: Unit[], foeSide: Unit[], rng: Rng): Command[];
function planAutoCommands(allies: Unit[], foeSide: Unit[], items: { heal: number }, rng: Rng): Command[];
```

均为纯函数（同样输入 + 同样 RNG ⇒ 同样指令），联机可原样放服务器。`planAutoCommands` 会**递减传入的 `items.heal`**，调用方应传副本（`Battle.planAllyAutoCommands` 已如此处理）。

## 11. 素材清单契约 `public/assets/manifest.json`

```json
{
  "<角色 defId>": {
    "frameSize": [48, 48],
    "anims": {
      "idle":   { "frames": ["sprites/xiake/idle_0.png", "..."], "fps": 2.5, "loop": true },
      "walk":   { "frames": ["..."], "fps": 9,  "loop": true },
      "attack": { "frames": ["..."], "fps": 12, "loop": false },
      "cast":   { "frames": ["..."], "fps": 8,  "loop": false }
    }
  },
  "$scenes": { "default": "scenes/heifengling.png", "taoyuan": "scenes/world_taoyuan.png", "...": "..." }
}
```

上例为 `xiake` 的实际帧率（`idle 2.5 / walk 9 / attack 12 / cast 8`），不同角色的帧数与帧率可能不同，一律以清单为准。

- 角色键必须等于 `CLASSES` / `PETS` / `MONSTERS` 的 id 或 `elder`；`$scenes` 键对应 `WorldMap.scene` 或 `ENCOUNTERS.id`，缺失时回退 `default`。
- 缺少某角色键时该单位**不渲染**（战斗/世界均 `if (!cm) continue`）。新增怪物或职业时必须同步 `tools/gen-assets.mjs` 的 `CHARS` 并重新生成素材。
- 只要文件名与清单一一对应，逐张替换 PNG 即可换美术，代码无需改动。

## 19. 一景一制接口（模块 12；取代模块 11 的统一 128×128 口径）

```ts
// tools/gen-iso-maps.mjs —— 确定性生成器，入口 npm run maps（幂等，末尾自带 BFS 自检）
// 输出 public/assets/art/iso/{wild_heifeng,wild_luanzang,wild_shanxiao,difu}.json
interface LayoutFile {
  grid: IsoGrid;                 // 必须与 ISO_GRIDS[id] 逐字段一致：每图 cols/rows 不同
  rules: { streetWidth: number; houseClearanceFromStreetCenter: number; roofLift: number };
  signature: string;             // switchback-ridge / diagonal-river / ring-cavern / straight-road
  tagline: string;
  size: { width: number; height: number };   // =(cols+rows)×32 / =(cols+rows)×16
  anchors: {
    spawns: Array<{ gx: number; gy: number; group: string[] }>;
    exits: Array<{ gx: number; gy: number; to: string; toGx: number; toGy: number; label: string }>;
    npc?: { gx: number; gy: number; name: string };
  };
  items: IsoItem[];              // 地面按行 RLE 合并的矩形 + 构件；只使用 ISO_TYPES 已登记类型
}

// core/world.ts
export const ISO_GRIDS: Record<string, IsoGrid> = {
  taoyuan:       { cols:128, rows:128, tileW:64, tileH:32, ox:4096, oy:16 },  // 8192×4096
  wild_heifeng:  { cols:128, rows:96,  tileW:64, tileH:32, ox:3072, oy:16 },  // 7168×3584
  wild_luanzang: { cols:96,  rows:128, tileW:64, tileH:32, ox:4096, oy:16 },  // 7168×3584
  wild_shanxiao: { cols:104, rows:104, tileW:64, tileH:32, ox:3328, oy:16 },  // 6656×3328
  difu:          { cols:80,  rows:112, tileW:64, tileH:32, ox:3584, oy:16 },  // 6144×3072
};
const at = (mapId: string, gx: number, gy: number) => cellToWorld(isoGridOf(mapId), gx, gy);
const isoSpawn = (mapId, gx, gy, group) => MapSpawn;                 // 用源图格网
const isoNpc   = (mapId, gx, gy, name) => { x; y; name };
const isoExit  = (mapId, gx, gy, to, toGx, toGy, label, r?) => MapExit;
//   x/y  = at(mapId, gx, gy)      路牌在源图
//   toX/toY = at(to, toGx, toGy) 落点必须用【目标图】格网换算
```

**格网公式**：`ox = rows × tileW/2`、`oy = tileH/2`，使 cell(0,0) 的上顶点贴 (0,0)；世界 `w=(cols+rows)×tileW/2`、`h=(cols+rows)×tileH/2`。`expandMap()` 的等距分支据此自动推导 `w/h/bounds = {0,0,w,h}`，具体可走性完全交给 `iso.buildCollision()`。

**边界契约**：所有 `exits[].gx/gy` 与 `toGx/toGy` 必须满足 `gx ∈ {1, cols−2}` 或 `gy ∈ {1, rows−2}`（用**各自图**的 cols/rows 判定）；成对路牌互为对方落点，即 `A→B` 的 `toX/toY` 必须等于 B 图中某条路牌的 `x/y`。拓扑：云京(16,1) ⇄ 山道(32,1)、山道(1,62) ⇄ 忘川(11,1)、山道(126,62) ⇄ 洞天(1,52)、忘川(73,126) ⇄ 地府(40,1)，地府(40,110) 单向还阳回云京(16,1)。

**验证契约**：`npm test` 逐条比对 `grid` 与 `ISO_GRIDS`、`anchors` 与 `BASE_MAPS`；校验所有玩法点与跨图落点 `isoWalkable === true`、每个出入口与全部玩法点两两 `findIsoPath` 连通、四图 `signature` 与地表组合互异、水面不可走 / 桥面可走 / 牌坊券洞可穿行。生成器自身也做四邻接 BFS 自检，锚点落进障碍会直接抛错。改布局后跑 `npm run maps && npm test`。

**表现层 variant**：`tree`（`leaf` / `pine` / `dead`）、`rock`（`moss` / `dark` / `crystal`）、`bridge`（`dark`）、`hall`（`stone`）等 variant 现在全部对应同名真实 PNG —— `isoModuleCandidates(type, variant, facing)` 先试 `art/iso/<type>_<variant>.png`，再退回 `art/iso/<type>.png`；`house` 走 `isoHouseCandidates(facing, variant)` 的成套屋身图。`v0.15.0` 已补齐 12 张场景构件贴图，`npm test [18]` 会展开五图逐条验证候选链零缺图。程序化占位（`drawRock` / `drawBridge` / `drawStele` 等）仅在找不到任何候选图时命中；既无模块图、又无专画类型的构件只留极淡落点标记，不会生成裸体方盒。
